CV Creation using LLMs - Architecture
======================================

One pipeline, one entry point: main.py. Whether a CV is tailored to a target
job or just polished on its own depends only on whether -jd is given.

------------------------------------------------------------
main.py  (single entry point)
------------------------------------------------------------
Run:
  py main.py -input <input_folder> -output <output_folder> [-jd <job_description_file>]

  -jd given    -> tailored mode: match + evidence-backed rewrite for one job
  -jd omitted  -> profile mode: polish each candidate's own facts, no target job
                  (this is the mandatory core task: 10 profiles -> 10 CVs)

Steps:
1. Parse args (-input, -output, optional -jd); load every resume .txt in the
   input folder.
2. If -jd given: extract job description -> extract_and_parse.py : ParseJob
   (Llama 2) - job description text -> {title, company, required_skills,
   preferred_skills, responsibilities, ...}. Saved once as
   parsed_job_description.json.
   For each resume:
3. Extract resume  -> extract_and_parse.py : ExtractResume (Llama 2)
   - resume text -> {name, email, phone, experience, skills, education, ...}
   - resumable: skipped and loaded from disk if <stem>_extracted_resume.json
     already exists in the output folder.
4. Quality check (extraction) -> quality_check.py : check_extraction
   (rule-based, no LLM) - flags missing name/contact/experience/skills.
5a. Tailored mode (-jd given):
    - Match skills    -> match_skills.py : MatchSkills (pure Python, no LLM)
      normalises skill phrases (aliases, filler words, protected multi-word
      terms), computes required/preferred coverage %, produces
      fabrication_blocklist: skills the job wants that the resume can't prove.
    - Retrieve evidence -> retrieve_evidence.py : RetrieveEvidence (pure Python)
      splits resume prose into sentences, finds the supporting sentence(s) for
      each matched skill, falls back to "Listed in skills" when none exists.
    - Generate CV      -> generate_tailored_cv.py : GenerateCV (Gemma 3 1B)
      model sees ONLY job details + evidence + blocklist, never the raw
      resume; output {summary, experience[].bullets, ordered_skills}; a hard
      post-generation filter strips any blocklisted skill that slips through.
5b. Profile mode (-jd omitted):
    - Generate CV      -> generate_profile_cv.py : ProfessionalCVGenerator
      (Gemma 3 1B) - no target job; only polishes the candidate's own stated
      facts (clearer summary, stronger action-verb bullets) - never invents
      employers, numbers, titles, or tools not already present.
    - Both generation steps are resumable the same way as extraction, via
      <stem>_generated_cv.json.
6. Quality check (generated CV) -> quality_check.py : check_generated_cv
   (rule-based, no LLM) - flags empty summary, placeholder text, missing
   bullets, or an unrecognised company introduced into the generated CV.
7. Render documents -> render_document.py + document_style.py
   - shared ATS-friendly styling: single column, standard font, plain black
     text, plain-text section headings, real bullet lists.
   - writes both .docx (python-docx) and .pdf (reportlab) from the same CV
     JSON, regardless of which mode produced it.
8. Save outputs to -output folder: per-resume stage JSON
   (*_extracted_resume.json, [*_match.json, *_evidence.json,] *_generated_cv.json)
   plus the final CV docx/pdf, and (tailored mode only) one shared
   parsed_job_description.json.

------------------------------------------------------------
Shared building blocks
------------------------------------------------------------
- json_utils.py    : extract_json/invoke_json - pulls a JSON object out of an LLM
                      response, repairing common local-LLM mistakes (trailing commas,
                      dropped closing quotes), retries on failure; save_json/load_json.
- document_style.py: shared ATS-safe styling constants/helpers used by both .docx
                      and .pdf renderers.
- quality_check.py : rule-based sanity gate shared by both modes - no LLM.
- LLM backend      : two local models via Ollama (langchain_ollama.OllamaLLM),
                      orchestrated with LangChain PromptTemplate + chain.invoke()
                      in every LLM-calling module - see "LLM used and purpose".

------------------------------------------------------------
LLM used and purpose
------------------------------------------------------------
Two different local models are used for two different jobs, both served
through Ollama with no cloud API calls - inference runs entirely on-device,
so no resume/job data ever leaves the machine.

  Llama 2 (llama2:7b)    - EXTRACTION only: turning messy free text into
                           structured JSON. Chosen for extraction because it
                           is the larger, more general-purpose model, better
                           suited to reliably parsing varied resume/job
                           formats into exact fields.

  Gemma 3 1B (gemma3:1b) - GENERATION only: rewriting already-structured,
                           evidence-backed facts into polished CV prose.
                           Chosen for generation because it is lightweight
                           and fast for the tailoring/rewriting workload,
                           where the facts are already pinned down and the
                           model's job is phrasing, not extraction accuracy.

Call sites:
  1. ExtractResume            extract_and_parse.py        Llama 2     temp=0.3
     Purpose: extract structured fields from a raw resume - name, contact,
     years of experience, summary, work history, skills, education,
     certifications, languages.

  2. ParseJob                 extract_and_parse.py        Llama 2     temp=0.3
     Purpose: extract structured fields from a raw job description - title,
     company, experience level, required/preferred skills, responsibilities,
     team size. Only runs when -jd is given.

  3. ProfessionalCVGenerator  generate_profile_cv.py      Gemma 3 1B  temp=0.4
     Purpose: rewrite a candidate's own stated facts into a polished,
     professional summary and achievement-style bullets - no target job,
     so this only improves wording, never adds a skill or claim.
     Only runs when -jd is omitted.

  4. GenerateCV                generate_tailored_cv.py    Gemma 3 1B  temp=0.4
     Purpose: rewrite the candidate's evidence-backed experience into a CV
     tailored to one target job's language and responsibilities, using only
     evidence the resume can prove and excluding blocklisted skills.
     Only runs when -jd is given.

Why the temperatures differ: extraction (0.3) needs faithful, literal parsing
of what is already on the page, not creative rewriting. Generation (0.4)
allows some latitude in phrasing/wording while the facts themselves stay
pinned to whatever evidence or blocklist the prompt supplies - neither model
is ever the source of truth for what the candidate did, only for how it is
phrased.

------------------------------------------------------------
Design principle: no fabrication
------------------------------------------------------------
The tailored generator (GenerateCV) never sees the raw resume - only evidence
snippets proven to exist in it, plus a blocklist of unprovable skills - and a
code-level filter strips any blocklisted skill the model outputs anyway. This
is enforced twice: once by what the prompt is given, and once by post-processing
that does not trust the LLM to have followed instructions. The profile-mode
generator (ProfessionalCVGenerator) enforces the same principle by construction:
it is never given a target job to fabricate a fit for, only the candidate's
own stated facts to polish.
